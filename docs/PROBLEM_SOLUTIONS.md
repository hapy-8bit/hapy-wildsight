## 2. 本轮已实施：发现页与识别入口

### 2.1 拍照识别无法正常唤起摄像头（已实施）

涉及：

- `entry/src/main/ets/services/PhotoService.ets`
- `entry/src/main/ets/App.ets`
- `entry/src/main/ets/pages/discovery/DiscoverPage.ets`
- `entry/src/main/module.json5`

本轮处理：

1. 在打开 CameraPicker 前请求模块已声明的 `ohos.permission.CAMERA`；拒绝时回到发现页并保留相册识别。
2. 按本机 SDK 运行时要求用对象字面量创建 `PickerProfile`，并通过应用沙箱文件 URI 设置 `saveUri`，避免对只读属性做实例赋值。
3. 相机返回 URI 后继续调用既有 `startIdentification(photoUri)`，没有重写识别链路。

真机设备 `2UCUT23C27028737` 已验证：发现页拍摄区 → 系统相机 → 拍照预览 → 确认 → “识别结果”，照片能够显示。

没有引入持续相机预览、额外权限或新的相机框架。

### 2.2 “从一次相遇开始”改为正方形拍摄区域（已实施）

当前发现页空状态是横向文字卡片。目标是改成 1:1 正方形拍摄入口：

- 使用现有主题 Token 和相机系统图标；
- 点击整个区域触发 `onTakePhoto()`；
- 保留“从相册识别”；
- 有 `heroPhotoUri` 时继续显示已选照片预览；
- 不引入外部图片或大面积新插画；
- 不让区域挤压底部 Tab 或产生横向溢出。

发现页空状态和已选照片预览均使用 1:1 区域；点击整个区域触发 `onTakePhoto()`，相册识别按钮仍保留。

### 2.3 移除发现页“最近发现”（已实施）

删除发现页中的完整“最近发现”区块，包括列表、空状态、查看图鉴和点击跳转；同步清理 `DiscoverPage` 的无用 Prop、回调、方法和 import，以及 `App.ets` 的无用传参。没有删除图鉴页的相遇数据。

### 2.4 把识别建议移到发现页（已实施）

当前“识别更准确的小建议”位于 `AtlasPage.ets` 的 `GuidanceCard`。目标：

- 从图鉴页移除；
- 在发现页的拍摄区域和按钮之后展示；
- 保留“尽量拍清叶片、花朵或整体形态”等文案；
- 可提取到 `components/`，但不能在两个页面各保留一份。

建议卡片现位于发现页拍摄区域和识别按钮之后，图鉴页不再保留副本。

### 2.5 统一二级页面标题栏（已实施）

`我的图鉴`、识别结果、相遇详情、物种详情和设置详情页共用 `SecondaryPageHeader`。实现参考 HarmonyOS 官方二级页标题栏的结构：安全区连续背景、左侧圆形返回按钮、大标题固定在顶部；内容滚动到标题栏下方后显示轻微遮罩和阴影，返回动作仍由现有应用内路由处理。浅色和深色均使用 `AppColors` 主题 Token，不引入新的 Logo 或图片。

没有把当前路由模型强行改造成新的 `Navigation` 栈，也没有影响底部 `HdsTabs`。

## 3. 已知风险

### 照片 URI 长期可读性

当前只保存 PhotoPicker/CameraPicker 返回的 URI，没有应用沙箱媒体副本。应用重启、系统清理或权限变化后的长期可读性尚未完整验证；后续应设计可恢复的媒体资产策略，不要在本轮 UI 修复中擅自扩大范围。

### 签名配置

`build-profile.json5` 含本机签名路径和明文凭据风险。正式交付前迁移到本机安全配置并轮换已暴露凭据；任何普通页面或知识库任务不得复制、输出或修改这些内容。

### 生产与真机状态

历史服务器健康检查和真机安装记录只代表记录日期，不代表当前重新验证。未联网、无 HDC 设备时必须如实报告。

每个问题修复后至少提供：

1. 根因和修改文件；
